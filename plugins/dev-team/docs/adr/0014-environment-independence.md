# 0014: 端末ごとに違う値は環境変数で受け取り、開発サーバーの停止スクリプトはプラグインに同梱する

- ステータス: accepted（2026-11-26）

## 背景
マーケットプレイスから入れたプラグインは、バージョンごとのキャッシュのコピーから読み込まれる。それまでの dev-team は、作者の端末の配置に 3 か所で依存していた。

- manager は、フロー改善（スキル・ルール・設定）の起票先を「プラグインが置かれた git リポジトリ」から導いていた（ADR 0013）。キャッシュのコピーは git の管理下に無いので、導けない
- dev-loop は、開発サーバーの停止をプラグインの外にある停止スクリプト（作者の端末の絶対パス）に頼っていた。スクリプトは「停止してよいプロセスの cwd」をホームディレクトリ以下の特定のディレクトリで判定していた
- manager とダッシュボードは、状態ファイル（manager-log・下書き・Herdr の記録・台帳）を `~/.claude/dev-team/` に固定で置いていた

## 決定
- **フロー改善の起票先は環境変数 `DEV_TEAM_FLOW_REPO`（ローカルの絶対パス）で受け取る**。manager は起動時に `git -C` でリポジトリであることを確かめ、失敗したら止まる。未設定なら迂回はせず、フロー改善の話題はどこで直すかを人に聞く
- **状態ファイルの置き場は環境変数 `DEV_TEAM_HOME` で受け取る**。未設定なら従来どおり `~/.claude/dev-team`。manager とダッシュボードが同じ規則で解決する
- **停止スクリプトは dev-loop スキルに同梱する**（`skills/dev-loop/scripts/stop-dev-server.sh`、SKILL.md からは `${CLAUDE_SKILL_DIR}` で参照する）。停止してよい cwd の範囲は、呼び出し側が `--root` で渡す必須の引数にする。dev-loop は `<メインリポジトリ>/.claude/worktrees` を渡す

## 検討した選択肢
- `${CLAUDE_PLUGIN_DATA}` を状態ファイルの置き場にする: プラグインの標準の置き場だが、ダッシュボードは Node のプロセスとして起動され、台帳の場所を別の経路で渡す必要が出る。manager とダッシュボードで同じ規則を持てる環境変数に寄せた（ADR 0006 で、スキルの Bash からこの変数が見えなかった経緯もある）
- 起票先を設定ファイル（JSON）で持つ: 読み込む手順を各スキルに持たせることになる。Claude Code の `settings.json` の `env` で渡せる環境変数のほうが標準の機構に乗る
- 停止スクリプトの範囲を固定のディレクトリのまま残し、利用者に書き換えてもらう: 同梱したファイルを利用者が直す前提になり、更新で上書きされる。範囲はチケットのワークツリーで足りるので、引数で絞るほうが狭く安全

## 影響
- 起票先と状態ファイルの置き場は、利用者が `settings.json` の `env` などで設定する。どちらも未設定で動く（迂回なし・既定の置き場）
- 停止スクリプトの範囲が「そのリポジトリの `.claude/worktrees/` 配下」に狭まり、他のリポジトリのワークツリーで動くサーバーを止めなくなる。dev-loop の孤児サーバーの列挙も同じ範囲に絞る
- background の dev-loop が許可待ちで止まらないよう、利用者は停止スクリプトの呼び出しを許可ルールに入れる必要がある（パスはプラグインの読み込み元で変わる）
