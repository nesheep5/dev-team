# 0005: アプリ仕様は SSoT として維持し、ADR は人が参加する工程だけが書く

- ステータス: accepted（2026-08-15）

## 背景
機能ごとの日付付き仕様書を積み重ねると全体像が分からなくなる。要件のたびに全体仕様を更新し続けたい。設計判断の経緯も残したい。

## 決定
- アプリ仕様は「現在の仕様」だけを書く生きたドキュメント群（既定 `docs/spec/`、領域ごとに1ファイル）として持ち、spec-intake が要件のたびに差分を更新する。セクションは見出し直前の `<a id="kebab-id"></a>` で恒久 ID を持ち、チケット・ADR・PR はこの ID で参照する
- チケットは仕様セクションを参照する。仕様と実装のずれの一覧 = ready / in-progress / awaiting-review のチケット群
- ADR は spec-intake（壁打ちで設計判断が出たとき）と dev-retro（振り返りで決定したとき）だけが書く。dev-loop は仕様に無い設計判断が必要になったら blocked にして intake に差し戻す

## 検討した選択肢
- 機能ごとの仕様書を積む: 全体像が失われる（今回の要件そのもの）
- 見出し文言のアンカーで参照: 見出しを直すたびに参照が壊れる
- `{#id}` 記法: GitHub のレンダラが解釈せず、そのまま表示されて見苦しい
- dev-loop にも ADR を書かせる: 自律エージェントが決定を積み SSoT が汚れる。実装上の細かな選択は PR 本文で足りる

## 影響
- 仕様の初期化（既存アプリの書き起こし）と、旧仕様書のアーカイブがプロダクト側の作業として発生する
- spec-intake の手順が「仕様の現状確認 → 差分 → ADR → 仕様 PR → チケット」に伸びる
