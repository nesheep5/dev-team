# 0009: 自然言語からの自動起動時は候補件数を示して許可を待つ

- ステータス: accepted（2026-09-06）

## 背景
dev-loop は description による自動起動を許している（「チケットを消化して」等）。一方でループは `status:ready` の全件を自動マージまで進めるため、意図しない起動の代償が大きい。description による自動選択は Claude の判断に委ねられており、この非対称を埋める関門が無かった。ADR 0002 の「人がいない時間も自律的に回る」性質は維持したい。

## 決定
- 対話セッションで、ユーザーが dev-loop を名指しせずに依頼した結果スキルが選ばれた場合、`status:ready` の件数と先頭数件のタイトルを示し、開始の許可を得てから起動時チェックに入る
- `/dev-team:dev-loop` の明示起動、およびサブエージェント・Workflow・`claude -p` など回答者のいない実行では確認しない
- 関門は起動時チェックより前に置く（起動時チェックはラベル付け替え・ワークツリー削除の副作用を持つ）

## 検討した選択肢
- `disable-model-invocation: true` で自動起動を止める: description が文脈から消え、Claude はスキルの存在を知らずに同等の作業を手作業で始めうる。提案してもらう体験も失う
- 無条件の許可関門: Workflow 並列や headless で回答者がおらず止まる。ADR 0002 の自律運転と矛盾する
- 関門なし（現状維持）: 誤起動で複数 PR が自動マージされる

## 影響
- 自然言語での起動は「提案 → 許可 → 開始」の 1 往復が増える。明示起動は変わらない
- friction-log の `step` に `startup-gate` を追加する
- `docs/spec/loop.md` に「起動関門」節を追加する
