# 0006: プロダクトごとの差は `.claude/rules/dev-team.md` の台帳で吸収する

- ステータス: accepted（2026-08-15）

## 背景
チケット管理（GitHub Issues / Jira）・開発ルール・PR 作成ルール・ドキュメント運用ルールはプロダクトごとに異なる。プラグインはフレームワーク部分だけを担い、具体はプロダクトのルールに合わせたい。スキル専用のメモリー機能は Claude Code に無い（公式ドキュメント確認済み）。

## 決定
- プロダクトの設定と既存ルールの所在は `.claude/rules/dev-team.md`（コミット対象。Claude Code がセッション開始時に自動ロードする共有指示ファイル）に書く。ルール本文は書かず、所在と選択だけを書く
- フレームワークは各概念の役割と契約（操作語彙・状態モデル・PR 必須要素・SSoT と ADR の存在）だけを固定し、具体は台帳で決める。`setup` スキルが既存ルールを検出して台帳に登録し、無いものだけ推奨既定を提案する
- ループの実行時データ（events.jsonl / review-log.jsonl）はプロジェクト内 `.claude/dev-team/`（gitignore）に置く。`${CLAUDE_PLUGIN_DATA}` はスキルの Bash から見えなかった（2026-08 時点の事前検証）。個人ローカル設定ファイル（`.local.md`）は作らず、認証情報は MCP か環境変数に置く

## 検討した選択肢
- `${CLAUDE_PLUGIN_DATA}` に置く: スキルの Bash から環境変数が見えず（同上）、書き込み先を決められない
- `.claude/dev-team.md` + `.local.md`（plugin-settings 慣習）: 公式ドキュメント未記載の慣習で、自動ロードもされないため各スキルが読む手順を持つ必要がある
- auto-memory に覚えさせる: 端末ローカルで git 管理・チーム共有ができない
- 設定ファイル（YAML）を独自に持つ: Claude Code 標準の共有指示機構に乗らない

## 影響
- 台帳は常時ロードされるため、短く保つ（所在と選択のみ）
- 全スキル・全サブエージェントが「読む手順」なしにトラッカーやルールの所在を知れる
- Jira の具体手順は最初の Jira プロダクトで `references/tracker-jira.md` に書く
