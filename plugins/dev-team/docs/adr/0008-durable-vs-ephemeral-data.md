# 0008: 実行時データを揮発データと累積データに分け、累積データはコミットする

- ステータス: accepted（2026-08-20）

## 背景
ADR 0006 は実行時データ（events.jsonl / review-log.jsonl）を一括で「プロジェクト内 `.claude/dev-team/`（gitignore）」に置くと決めた。しかしこの決定は ADR 0004 と矛盾する。

ADR 0004 は review-log をこう位置づけている。

- 「review-log の形式が計測と振り返りの共通契約になる」
- 「`human:*` の行が自動レビューをすり抜けた指摘であり、フィードバックループの主入力」

gitignore されたファイルは、クリーンチェックアウト・別マシン・CI 環境のいずれでも消える。数週間から数か月かけて蓄積する計測と振り返りの主入力を、消えるファイルに置くことはできない。ADR 0004 が events.jsonl を計測の正から外した理由（「端末ローカルで、セッションや端末をまたぐと欠ける」）は、review-log にもそのまま当てはまっていた。

## 決定
実行時データを性質で2つに分ける。

**揮発データ** — 現在のループの進行状況。`.claude/dev-team/`（gitignore）に置く
- `events.jsonl`: ダッシュボードが読む進行状況。ループごとにリセットされてよい
- `servers/*.json` / `logs/*.log`: 開発サーバーの記録とログ

**累積データ** — 計測と振り返りの入力。`.claude/dev-team-log/`（コミット対象）に置く
- `review-log.jsonl`: レビュー指摘の記録（ADR 0004）
- `friction-log.jsonl`: ループが自己申告した「指示の不備」の記録

累積データは追記のみ。マージコンフリクトを避けるため、1行1レコードの JSONL とし、行の書き換えと削除はしない。

## 検討した選択肢
- 全部 gitignore のまま（ADR 0006 の原案）: フィードバックループと計測が成立しない。ADR 0004 との矛盾が残る
- 全部コミット対象にする: events.jsonl は1ループで数十行増え、進行状況以上の価値が無いのに履歴を汚す。ダッシュボード用の揮発データにすぎない
- 累積データを GitHub 側（Issue コメント等）に置く: ADR 0004 の「GitHub を正とする」に沿うが、JSONL の構造化データを人間向けコメントに混ぜると集計が脆くなる。GitHub が正なのは PR・レビュー・ラベルという GitHub 本来のデータであって、プラグイン固有のログではない
- 別リポジトリに集約する: プロダクトを跨いだ集計はできるが、プロダクトごとの文脈（どの仕様・どのルールに対する指摘か）と切り離され、振り返りの根拠が弱くなる

## 影響
- ADR 0006 の実行時データの置き場の決定を部分的に上書きする（置き場を1つから2つに分ける）。ADR 0006 のステータスは変更しない。台帳の位置づけと `${CLAUDE_PLUGIN_DATA}` についての結論は有効なため
- 累積データがプロダクトのリポジトリに入るため、機微な情報（レビュー指摘に含まれる内部事情）が混ざらないか、記録時に注意が要る
- `.gitignore` に書くのは `.claude/dev-team/` のみ。`.claude/dev-team-log/` は追跡する
