# 0003: レビューの取り込み: 外部レビューは PR コメント経由、汎用レビューは pr-review-toolkit、UI 確認は探索的

- ステータス: accepted（2026-08-15）

## 背景
CI・CodeRabbit のような外部 AI レビュー・コードレビューサブエージェント・Playwright での動作確認を自動ゲートに含めたい。特定サービスやツールへの依存は最小にしたい。

## 決定
- 外部レビュアー（CodeRabbit・claude-code-action・人）は GitHub の PR コメント/レビューという標準インターフェースで汎用に取り込む。CI 失敗も同じ土俵の指摘として扱う。導入自体はプロダクト側の判断（台帳に外部レビュアーと待機時間を書く）
- 汎用コードレビュー（バグ・テスト網羅・エラーハンドリング）は pr-review-toolkit の3エージェントを soft dependency として使い、無い環境では汎用エージェントで代替する。プラグイン固有の観点（仕様一致 = spec-reviewer、UI 動作確認 = ui-verifier）だけ自前エージェントにする
- UI 動作確認は探索的に行い、結果とスクリーンショットを PR に貼る。E2E テストのコード化は受け入れ条件に `[e2e]` が付いた項目だけ

## 検討した選択肢
- CodeRabbit をプラグインが直接組み込む: 特定サービス依存になる
- レビュアーを全部自前エージェントにする: チューニング済みのものを複製しても保守が増えるだけ
- 全チケットで E2E をコード化: E2E 基盤の整備・保守がループのボトルネックになる

## 影響
- レビュー指摘は source（subagent / external / human / ci）を区別して review-log に残す
- pr-review-toolkit が無い環境では品質が下がる（代替エージェントで補う）
