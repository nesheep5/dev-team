# 0002: 人間ゲート: draft PR → 自動ゲート → Approve 検知でループがマージする

- ステータス: accepted（2026-08-15）

## 背景
現行 dev-loop はレビュー反復の合格後に自動マージしていた。人の最終コードレビューを入れつつ、人がいない時間も自律的に回る性質は残したい。

## 決定
- PR は draft で作り、CI・外部レビュー・サブエージェントレビュー・UI 動作確認の自動ゲートに合格したら `gh pr ready` で人に渡す（`status:awaiting-review`）
- 人は GitHub 上で Approve だけ行う。ループは起動時と終了前の回収フェーズで、最新コミットへの Approve かつ CI 緑の PR を main 取り込み → 検証 → squash マージ → 後片付けする
- 承認待ちの間、依存関係のないチケットだけ先へ進む。依存先が未マージ（awaiting-review 含む）のチケットはスキップする
- 自動ゲートの往復は最大3回、人の往復は無制限。ループは承認を待って居座らず、次回起動時に回収する

## 検討した選択肢
- 承認が出るまでそのチケットで待つ: 人がいない時間にループが止まり、自律運転の価値を殺す
- 承認待ちでも依存チケットを未マージブランチ上に積む: リベース地獄になりやすい
- 人がマージまで行う: マージ後の後片付け・後続 PR への main 取り込みの責任が曖昧になる

## 影響
- awaiting-review の PR が複数積み上がりうる。実装中は同時1件のまま
- ラベル `status:awaiting-review` を追加する
- ループが動いていない時間帯の Approve は次回起動まで回収されない
